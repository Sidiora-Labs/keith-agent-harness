## इसे आज़माएँ

सबसे छोटा रास्ता Docker है:

```bash
cp .env.example .env
# .env में KEITH_WEB_LOGIN_SECRET और एक मॉडल-प्रदाता कुंजी सेट करें।
docker compose up --build
```

<http://localhost:7341> खोलें। Keith अपनी स्थिति `keith-data` वॉल्यूम में रखता
है और मौजूदा चेकआउट के `/workspace` के अंदर काम कर सकता है।

स्रोत से विकास करना पसंद है?

```bash
./keith doctor
./keith setup
./keith dev
```

TUI, प्रदाता सेटअप, अपग्रेड, बैकअप और सेवा प्रबंधन के लिए
[इंस्टॉलेशन गाइड](docs/installation.md) देखें।

## Keith कैसे विकसित होता है

हर रन Keith को सिर्फ एक ट्रांसक्रिप्ट से अधिक देता है। यह पूरे एजेंट के प्रदर्शन
के बारे में साक्ष्य उत्पन्न करता है: तर्क का मार्ग, टूल चयन, संदर्भ उपयोग,
विलंबता, लागत, रिकवरी और अंतिम परिणाम।

एक कठिन विफलता विकास का अवसर उजागर कर सकती है, लेकिन एक बेकार टूल कॉल, धीमी
रिकवरी, या एक ऐसा परिणाम जो बेहतर होना चाहिए था — वही कर सकते हैं।

Keith सबसे मज़बूत अवसर को एक परीक्षण योग्य परिकल्पना में बदलता है, लाइव सिस्टम
से दूर कई उम्मीदवार हार्नेस बनाता है, और प्रस्तावक को जो काम नज़र नहीं आया
उस पर उन्हें मौजूदा संस्करण से तुलना करता है। कोई उम्मीदवार तभी आगे बढ़ता है
जब वह प्रतिगमन पैदा किए बिना मापने योग्य सुधार लाता है।

```text
अनुभव → अवसर → परीक्षण योग्य परिकल्पना → उम्मीदवार हार्नेस
     → होल्ड-आउट मूल्यांकन → केनरी → निरीक्षण → रखें या वापस लें
```

यही Keith के पीछे का केंद्रीय दाँव है: एक एजेंट को केवल काम नहीं करना चाहिए।
उसके पास काम करने में बेहतर होने का एक सुरक्षित, निरीक्षणीय तरीका होना चाहिए।

### काम करते हुए ठीक करें

Keith Computer एक दृश्य, अलग-थलग डेस्कटॉप है। रन को लाइव देखें, एक क्रिया
में कीबोर्ड और पॉइंटर अपने हाथ में लें, समस्या ठीक करें, फिर नियंत्रण वापस
दें। एक विशेष नियंत्रण पट्टा यह रोकता है कि आप और Keith एक ही स्क्रीन के लिए
भिड़ें।

### काम सिखाएँ, एक और प्रॉम्प्ट नहीं

जब आप कोई कार्य प्रदर्शित करते हैं, तो Keith उसके पीछे की उपयोगी संरचना रिकॉर्ड
करता है: स्क्रीन स्थिति, कीबोर्ड और पॉइंटर क्रियाएँ, UI लक्ष्य, एप्लिकेशन संदर्भ,
टाइमिंग, विवरण, फ़ाइलें, क्लिपबोर्ड गतिविधि और हर नियंत्रण हस्तांतरण। वह इन
साक्ष्यों को इनपुट, चेकपॉइंट, अनुमोदन, रिकवरी चरण, संस्करण और रोलबैक के साथ
एक संपादन योग्य **TaskRecipe** में बदल देता है।

आप Keith को सिर्फ एक स्क्रीन रिकॉर्डिंग नहीं दे रहे हैं। आप उसे काम का एक टुकड़ा
दिखा रहे हैं जिसे वह फिर से चला सकता है और सुधार सकता है।

### हार्नेस की मरम्मत करने दें, नियमों की नहीं

स्व-मरम्मत तभी उपयोगी है जब उम्मीदवार गोल पोस्ट नहीं हिला सकता। Keith के मरम्मत
उम्मीदवार न्यायाधीश, होल्ड-बैक टेस्ट केस, क्रेडेंशियल, Keith जो याद रख सकता
है या प्रकट कर सकता है, आपके अनुमोदन नियम, रिलीज़ जाँच, प्रमोशन गेट या रोलबैक
पथ को संपादित नहीं कर सकते।

तय करें कि Keith कितनी दूर तक जा सकता है:

- **केवल सलाह**   प्रस्तावित मरम्मत समझाएँ और प्रतीक्षा करें।
- **शैडो परीक्षण**   उम्मीदवार बनाएँ और परीक्षित करें, पर किसी को प्रोन्नत न करें।
- **स्वायत्त मरम्मत**   आपके निर्धारित सीमाओं के भीतर केनरी, निरीक्षण और वापसी।

हर मोड में संरक्षित नियम मरम्मत उम्मीदवार की पहुँच से बाहर रहते हैं।

### एक Keith, बॉट्स के फ़ोल्डर नहीं

Web UI, TUI, OpenAI-संगत API, मूल API, ACP क्लाइंट, मैसेजिंग चैनल, जुड़े ऐप्स
और कंप्यूटर — सब एक ही डेमॉन-स्वामित्व वाले एजेंट तक पहुँचते हैं। विशेषज्ञ
वर्कर पर्दे के पीछे शोध, कोडिंग या टूल संचालन कर सकते हैं, बिना उत्पाद को
प्रबंधन के लिए व्यक्तित्वों से भरे डैशबोर्ड में बदले।

सत्र क्लाइंट डिस्कनेक्ट के बाद भी जीवित रहते हैं। प्रतिबद्धताएँ, प्रतीक्षाएँ,
निर्धारित कार्य, लक्ष्य और सक्रिय रन पुनरारंभ के बाद पुनर्प्राप्त हो सकते हैं।
टर्मिनल में शुरू करें, Slack से जाँचें, और ब्राउज़र में समाप्त करें — बिना तीन
असंबंधित सहायक बनाए।

## Keith के साथ आप क्या कर सकते हैं

| आप चाहते हैं… | Keith कर सकता है… |
| --- | --- |
| ब्राउज़र या डेस्कटॉप कार्य सौंपना | हेडेड या हेडलेस कंप्यूटर में काम करना, जबकि आप देखें, रोकें या नियंत्रण लें |
| एक दोहराने योग्य कार्यप्रवाह सिखाना | लाइव प्रदर्शन को संपादन योग्य, पुनः चलाने योग्य TaskRecipe में बदलना |
| एक ही एजेंट विफलता को बार-बार रोकना | हार्नेस का निदान करना, प्रतिस्पर्धी मरम्मत परीक्षित करना, विजेता को केनरी पर लाना और वापस लेना |
| अपने स्वयं के मॉडल का उपयोग करना | OpenAI, Anthropic, OpenRouter, Ollama या अन्य समर्थित प्रदाता के माध्यम से प्रोफ़ाइल रूट करना |
| कहीं से भी उसी एजेंट तक पहुँचना | Web, TUI, ACP, API, Discord, Slack, Telegram, WhatsApp, Teams, Google Chat, ईमेल और Matrix क्लाइंट को सेवा देना |
| वास्तविक सेवाएँ जोड़ना | अनुमोदन-गेटेड जुड़े ऐप्स, Composio, MCP सर्वर और क्षमता-स्कोप्ड WASI प्लगइन्स का उपयोग करना |
| Keith के ऊपर निर्माण करना | OpenAI-संगत `/v1` API या टाइप्ड मूल `/platform/v1` API का उपयोग करना |
| अपनी अवसंरचना पर चलाना | Docker, Kubernetes, Railway, Fly.io, DigitalOcean, Azure, AWS या Google Cloud के साथ तैनात करना |

## एक रनटाइम, कई प्रवेश बिंदु

```text
Web · TUI · OpenAI API · Platform API · ACP · चैनल
                         │
                      agentd
              सत्र · नीति · रिकवरी
                         │
                पट्टे पर एजेंट वर्कर
                         │
       मॉडल · टूल · प्लगइन्स · CUA · जुड़े ऐप्स
```

`agentd` सत्य का मालिक है। क्लाइंट अपनी स्वयं की स्थिति गढ़ने के बजाय उसके
सत्र और जीवनचक्र को प्रस्तुत करते हैं। वर्कर पट्टे के अधीन टर्न निष्पादित
करते हैं, और डोमेन क्रेट नीति को बाहरी अडैप्टर से अलग रखते हैं।

पूर्ण सिस्टम मानचित्र के लिए [क्रेट गाइड](docs/crate-guide.md) और
[निर्भरता सीमाएँ](docs/architecture/dependency-boundaries.md) पढ़ें।

## API और एक्सटेंशन

Keith दो HTTP सतहें प्रस्तुत करता है:

- **OpenAI-संगत `/v1`** — मौजूदा SDK और Open WebUI जैसे टूल के लिए।
- **मूल `/platform/v1`** — उन विश्वसनीय क्लाइंट के लिए जिन्हें Keith के सत्र,
  जीवनचक्र, अनुमोदन, आर्टिफ़ैक्ट और लाइव इवेंट चाहिए।

एक्सटेंशन क्षमता-स्कोप्ड WASI घटकों, MCP सर्वर, कौशल, या अनुमोदन-गेटेड
जुड़े ऐप्स के रूप में चल सकते हैं। ACP क्लाइंट बंडल किए गए stdio सर्वर के
माध्यम से जुड़ सकते हैं। देखें
[OpenAI अनुकूलता](docs/openai-compatibility.md) और
[प्लेटफ़ॉर्म एकीकरण](docs/platform-integration.md)।

## सुरक्षा

> [!WARNING]
> Keith कमांड चला सकता है, फ़ाइलें बदल सकता है, ब्राउज़र नियंत्रित कर सकता है
> और आपके द्वारा दी गई अधिकारिता के साथ बाहरी सेवाओं को कॉल कर सकता है। ऐसी
> वर्कस्पेस का उपयोग करें जिसे आप निरीक्षण और पुनर्स्थापित कर सकें। मॉडल
> आउटपुट, चैनल संदेश, लाए गए पृष्ठ, प्लगइन्स, कौशल, MCP सर्वर और मरम्मत
> उम्मीदवारों को अविश्वसनीय मानें।

जब तक आप TLS, मज़बूत प्रमाणीकरण और स्पष्ट नेटवर्क नीति नहीं जोड़ते, Web UI
और API को loopback पर रखें। Web लॉगिन, API, मॉडल प्रदाता और रिलीज़ हस्ताक्षर
के लिए अलग-अलग सीक्रेट का उपयोग करें। क्रेडेंशियल या अनरेडैक्टेड ट्रेस
को कभी सार्वजनिक issue में न पोस्ट करें।

कमज़ोरियों की रिपोर्ट निजी रूप से GitHub के
[security advisory फ़ॉर्म](https://github.com/Sidiora-Labs/keith-agent/security/advisories/new)
के माध्यम से दें। विश्वास मॉडल, दायरा और रिपोर्टिंग नियमों के लिए
[SECURITY.md](SECURITY.md) पढ़ें।

## तैनाती

Keith एक ही stateful OCI इमेज के रूप में आता है, Docker Compose, Helm
के साथ Kubernetes, Railway, Fly.io, DigitalOcean Kubernetes, Azure
Kubernetes Service, Amazon EKS और Google Kubernetes Engine Autopilot
के लिए समर्थित पथ के साथ।

```bash
./keith deploy kubernetes --render
./keith deploy railway
./keith deploy fly --app my-keith
./keith deploy aws --cluster keith --region us-east-1
```

क्लाउड कमांड डिफ़ॉल्ट रूप से एक योजना प्रिंट करते हैं। तैनाती केवल तभी
अवसंरचना बदलती है जब आप `--execute` पास करें और `KEITH_DEPLOY_APPROVED=YES`
सेट करें। होस्ट के बाहर Keith को उजागर करने से पहले पूरी
[तैनाती गाइड](docs/deployment.md) पढ़ें।

## विकास और विस्तार

`./keith` कमांड सेटअप, स्थानीय सेवाएँ, जाँच, परीक्षण, रिलीज़ बिल्ड, कंटेनर
इमेज, स्कैफ़ोल्डिंग और तैनाती योजनाओं के लिए योगदानकर्ता का प्रवेश बिंदु है।
Rust बिल्ड आउटपुट चेकआउट के बाहर रहता है।

```bash
./keith check
./keith test
./keith image keith-agent:dev
./keith scaffold plugin my-plugin
./keith scaffold skill my-skill
```

Rust 1.93, Node.js 22.22, Corepack और Git आवश्यक हैं। Pull request खोलने
से पहले [CONTRIBUTING.md](CONTRIBUTING.md) पढ़ें और जिन कमांड और वास्तविक
उपयोगकर्ता पथों को आपने चलाया उनकी रिपोर्ट दें।
